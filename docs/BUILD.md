# Исходники и сборка 4.137

## Состав

В `src` находятся 91 файл выгрузки Конфигуратора: основная обработка и восемь встроенных обработок-исполнителей. 20 модулей хранятся в BSL; ещё пять модулей обычных форм — внутри `Form.bin`. Эти формы редактируются в Конфигураторе. Двоичные контейнеры являются частью исходной выгрузки и не означают закрытый код.

Соответствие исполнителей макетам основной обработки перечислено в `tools/release.json`. В репозитории сохранены готовые двоичные макеты исполнителей, а также полный исходный код каждого из них.

Для работы пользователю достаточно готового EPF из Releases. Платформа 1С, базы, лицензия платформы и тестовые данные в репозиторий не входят.

## Проверка снимка исходников

Требуется Python 3.10 или новее, без дополнительных пакетов. Из корня репозитория:

```powershell
python tools/build.py --check
```

Проверяются SHA-256 всех исходных файлов и корректность XML. Это проверка целостности поставки, а не анализ или выполнение BSL.

## Сборка неизменённой 4.137

Требуются Windows, Python и установленный Конфигуратор 1С 8.3. Авторская сборка подготовлена платформой 8.3.27.2325. Используйте отдельную существующую файловую тестовую базу; Конфигуратор должен открываться в ней без интерактивных диалогов. Запускатель поддерживает пользователя без пароля и не сохраняет учётные данные.

```powershell
python tools/build.py --designer "C:\Program Files\1cv8\8.3.27.2325\bin\1cv8.exe" --base "D:\1C\BuildTest" --user "BuildUser"
```

Пути и имя пользователя в примере условные: укажите свои. Команда не создаёт базу и не обновляет её конфигурацию; используется операция сборки внешних обработок из файлов.

Сценарий:

1. Проверяет неизменность исходников 4.137.
2. Создаёт новую рабочую копию в `.build/<дата-время-идентификатор>/src`.
3. Собирает восемь исполнителей и вкладывает их EPF в соответствующие макеты рабочей копии.
4. Собирает основную обработку.
5. Проверяет, что исходная папка `src` осталась неизменной, и сохраняет SHA-256 результата.

Выходной EPF, журналы Конфигуратора и `build-result.json` находятся в созданном каталоге `.build`. Готовый выпуск из Releases не перезаписывается. Побайтовое совпадение повторной сборки с авторским EPF не гарантируется: бинарный формат и версия Конфигуратора могут влиять на результат.

## Изменение кода

Запускатель предназначен для повторной сборки опубликованного снимка 4.137. При изменении исходников он остановится: встроенные исполнители используют согласованный идентификатор сборки и имена метаданных, поэтому нельзя незаметно подменять код под прежним идентификатором.

Для разработки можно загрузить каждую внешнюю обработку из XML в Конфигуратор, отредактировать и сохранить исходники. При подготовке изменённого выпуска необходимо согласовать номер версии, возвращаемое значение `ИдентификаторСборки` во всех девяти модулях объектов, имена исполнителей и ссылки на них в XML, а затем обновить манифест поставки. Последовательность сборки остаётся прежней: исполнители → двоичные макеты → основная обработка.

Если меняется только основная обработка, неизменённые встроенные макеты доступны в её выгрузке. Для ручной сборки Конфигуратором используется `/LoadExternalDataProcessorOrReportFromFiles <исходный XML> <выходной EPF>`.

Изменения запросов проверяйте реальным выполнением на тестовой базе. Успешная сборка не подтверждает работу форм и запросов. Известные результаты авторских проверок приведены в [COMPATIBILITY.md](COMPATIBILITY.md).
